# 系统托盘宿主与防失联热切换 规格

Status: ready-for-agent
Created: 2026-11-26

## Problem Statement

当前 `nexus-mcp` 在 Windows 本机日常使用与自举开发上存在两类突出摩擦：

1. **常驻与启停体验差**：开机自启依赖启动文件夹里的两份隐藏窗口 `.vbs` 脚本（一份拉起 `nexus-mcp.exe`，一份拉起 `cloudflared`），无托盘图标、无状态提示，想安全关停服务和**隧道**时无处下手；同时现有**隧道**采用 detached 启动，退出服务不会带走隧道，存在安全隐患。
2. **自举开发容易卡死或失联**：用源码仓里的 `npm run dev` 直接承接云端**连接器**时，改**协议层**代码不会重载，改**执行层**代码会因常驻 `nexus-executor.exe` 触发 Windows `os error 5` 文件锁；一旦改坏代码或忘起服务，云端 AI 会直接撞 502 失联，无法无人监管持续迭代。

## Solution

把「承载云端**连接器**的运行态」与「源码开发仓」物理隔离，并补齐单入口系统托盘与防失联**热切换**：

- **单 exe 托盘宿主**：在 Rust workspace 新增极轻量的 Win32 原生 GUI 托盘程序作为主入口 `nexus-mcp.exe`（原 Node SEA **协议层**改名为同目录 `nexus-server.exe`）。无黑框启动、单实例保护、右下角展示三色**状态灯**图标与右键快捷菜单（含开机自启勾选），设置与**服务日志**仍留在浏览器**面板**。
- **隧道同生共死**：配置了**隧道**时默认随服务自动拉起，淘汰两份 `.vbs` 与 `启动.cmd`；点击托盘「退出」时连同**协议层**、**执行层**与**隧道**一并**树杀**停干净；仅重启服务或执行**热切换**时保持隧道不断，新进程启动后自动接管。
- **AI 自主延迟热切换与自动回滚**：将最小打包（跳过耗时 NSIS）+ 独立临时端口自检 + 延迟切换封装为统一本地部署脚本。AI 在源码仓改完代码并跑绿检查后可自主触发**热切换**；切换器在当前工具调用返回后延迟 1–2 秒备份旧产物为 `.prev`、替换并拉起新版本，10 秒内探测 `127.0.0.1:8787/health` 不过则自动还原 `.prev` 回滚，彻底避免把自己锯断失联。

## User Stories

1. 作为使用者，我想只把一个 `nexus-mcp.exe`（或其快捷方式）放进启动文件夹就能无黑框后台常驻，不再维护两份 `.vbs` 脚本，以便开机即用、不弹黑框。
2. 作为使用者，我想在 Windows 右下角任务栏看到**托盘宿主**图标，并通过颜色与悬浮提示一眼判断服务和**隧道**是否健康，以便不用每次手动开浏览器确认。
3. 作为使用者，我想左键双击托盘图标直接用默认浏览器打开**面板**，以便快速改配置或查**服务日志**。
4. 作为使用者，我想在托盘右键菜单里一键执行「打开控制面板」「重启 MCP 服务」「启动/停止隧道」「打开日志目录」「开机自启」与「退出」，以便日常操作不用翻终端。
5. 作为使用者，我想在启动 `nexus-mcp.exe` 且已配置**隧道**时自动拉起 `cloudflared`，以便开箱连通云端**连接器**。
6. 作为使用者，我想在托盘点击「退出」时确保**协议层**、**执行层**与**隧道**全部停干净且不触发**隧道守护**拉回，以便避免后台残留裸奔的公网隧道。
7. 作为使用者，我想在已运行 `nexus-mcp.exe` 时再次双击它不会起第二个冲突实例，而是直接帮我打开**面板**，以便避免端口占用报错。
8. 作为使用者，我想在托盘右键直接勾选/取消「开机自启」（只管理当前用户启动文件夹里的 `.lnk` 快捷方式），以便不用手动翻找 `shell:startup`。
9. 作为开发者，我想让承载云端**连接器**的运行实例固定跑在独立安装目录，源码仓只做开发、构建与测试，以便彻底告别 `os error 5` 文件锁与误杀当前会话。
10. 作为开发者，我想保留 `npm run dev`、`--stdio` 与自动化测试直跑**协议层**不弹托盘的行为，以便命令行调试与本地 CI 保持无头干净。
11. 作为自我调试的 AI，我想通过一条统一的本地部署命令完成最小打包、临时端口 smoke 与延迟**热切换**，以便无需人工介入就能把通过测试的新改动平滑发布到本机运行目录。
12. 作为自我调试的 AI，我想在**热切换**时保持**隧道**不断，且当**托盘宿主**自身未改动时由托盘内无缝换核（图标不闪退），以便切换耗时最短、连接器快速重连。
13. 作为使用者与 AI，我想在**热切换**后新版本 10 秒内无法通过 `/health` 校验时自动还原 `.prev` 回滚到上一稳定版并留下可读错误日志，以便哪怕改出启动崩溃也不会永久失联。
14. 作为使用者，我想在**热切换**过程中运行目录里的 `config.json` 与 `oauth-store.json` 始终原封不动，以便令牌、根目录和云端 OAuth 授权不丢失。

## Implementation Decisions

### 1. 模块划分与可执行文件形态（ADR-0008）

- **托盘宿主（Rust Win32 GUI crate）**：在 Rust workspace 新增原生 GUI 子系统二进制，打包对外命名为主入口 `nexus-mcp.exe`（无控制台窗口、不引 Electron/Tauri）。
- **协议层打包名变更**：原 Node 24 SEA 单文件产物更名为同目录 `nexus-server.exe`，由**托盘宿主**以无窗口子进程方式拉起并监管。
- **执行层不变**：同目录 `nexus-executor.exe` 继续由**协议层**按需拉起。
- **单实例保护**：**托盘宿主**启动时申请 Windows 命名 Mutex；若检测到已有实例运行，直接用默认浏览器打开**面板**地址并退出新进程。
- **无头模式保留**：`npm run dev`、`--stdio` 与测试套件继续直接启动**协议层**，不经过**托盘宿主**。
- **打包产物精简**：NSIS 安装包与绿色 zip 均包含 `nexus-mcp.exe` + `nexus-server.exe` + `nexus-executor.exe` + 使用说明，淘汰 `启动.cmd` 与旧 `.vbs` 启动脚本。

### 2. 托盘宿主与协议层协作边界

- **状态与控制复用面板本地 HTTP API**：**托盘宿主**定时轮询 `127.0.0.1:<panelPort>/api/status` 映射三色图标（绿 = 服务与隧道均就绪，黄 = 启动中或隧道未连/未配置，红 = 异常）与悬浮提示；右键操作直接调用 `/api/service` 与 `/api/tunnel`，不另造专有 IPC 协议。
- **右键菜单项**：
  1. `打开控制面板`（与左键双击同效）
  2. `重启 MCP 服务`（仅重置**会话**与**执行层**，不动**隧道**）
  3. `启动隧道` / `停止隧道`（随状态动态文案）
  4. `打开日志目录`
  5. `开机自启`（勾选状态同步当前用户启动文件夹内 `nexus-mcp.lnk` 是否存在，不修改系统注册表）
  6. `退出（同时停止服务与隧道）`

### 3. 隧道与退出生命周期边界（ADR-0008）

- **随服务自启**：在配置中新增 `tunnel.autoStart`（默认 `true`）。当配置了有效**隧道**参数且该开关为 `true` 时，**协议层**启动就绪后自动拉起 `cloudflared`（若已有外部 `cloudflared` 在跑则按既有接管逻辑纳管，不重复拉起）。
- **彻底退出 vs 仅重启/热切换**：
  - **退出**：**面板**提供本机专用优雅全停入口（或**托盘宿主**发停机指令），**协议层**收到后按顺序停止**隧道**（关闭**隧道守护**自动拉回）→ 停止 HTTP 服务 → 关闭**执行层**并**树杀**全部后台任务。若 3 秒内未退出，**托盘宿主**通过 Windows Job Object 强制**树杀**兜底。
  - **重启服务 / 热切换**：不停止**隧道**，仅关闭并重建**协议层**与**执行层**；新版**协议层**启动后自动重新接管运行中的 `cloudflared`。

### 4. 运行态隔离与防失联热切换（ADR-0009）

- **默认运行目录**：本机热切换默认指向安装目录 `C:\Users\Administrator\AppData\Local\Programs\nexus-mcp\`（支持通过环境变量覆盖，便于测试与换机）；切换全程严格跳过并保留目录内的 `config.json` 与 `oauth-store.json`。
- **统一本地部署命令**：保留**执行层**默认的 `MSYS_NO_PATHCONV=1`（防止破坏 Windows `/flag` 参数语义），用一条不依赖 pnpm POSIX `npm` wrapper 的统一脚本封装：
  1. 构建**执行层**、**托盘宿主**与**协议层**最小 SEA 产物（跳过耗时的 NSIS 打包）；
  2. 用刚生成的产物在临时端口跑通 smoke（起服务、调 `/health`、执行工具自检）；
  3. 通过后触发延迟切换，当前工具调用立刻返回已排队回执，避免在请求中途断连。
- **两条切换路径与自动回滚**：
  - **路径 A（托盘内无缝换核）**：检测到目标目录的 `nexus-mcp.exe` 哈希未变化时，通过本机控制接口交由运行中的**托盘宿主**在延迟 1–2 秒后执行：停旧 `nexus-server.exe`（不动**隧道**）→ 备份旧 `nexus-server.exe` / `nexus-executor.exe` 为 `.prev` → 拷入新产物 → 拉起新 `nexus-server.exe`。托盘图标全程不消失。
  - **路径 B（托盘自身更新）**：检测到 `nexus-mcp.exe` 哈希变化时，拉起脱离当前进程树的临时切换器，延迟 1–2 秒后停旧**托盘宿主**与 `nexus-server.exe`（同样不动**隧道**）→ 备份并替换全部变更 exe → 拉起新 `nexus-mcp.exe`。
  - **健康检查与回滚**：拉起新版后在 10 秒窗口内轮询 `127.0.0.1:<port>/health`（要求返回 HTTP 200 且进程存活）；若超时或进程提前退出，自动将 `.prev` 还原覆盖并重新拉起旧版，同时将失败原因与子进程 stderr 尾行写入可读日志供 AI 下一轮排查。

## Testing Decisions

### 好测试的标准

只测外部可观察行为（HTTP 响应、进程存活与退出码、磁盘产物与配置文件完整性、`.lnk` 存在性），不断言内部函数调用或私密报文格式，也不依赖脆弱的桌面 GUI 模拟点击。

### 公开测试缝隙

1. **缝隙 1 — 协议层与隧道生命周期（复用面板 HTTP API + 进程入口）**
   - 沿用 `tests/tunnel.test.ts` 与 `tests/panel.test.ts` 的 `startServer()` + `cloudflared` stub 模式；
   - 覆盖：`tunnel.autoStart` 启动自动拉起隧道、托盘退出全停同步终止隧道且不触发**隧道守护**拉回、重启/热切换期间隧道存活且新版自动接管。
2. **缝隙 2 — 托盘宿主生命周期与单实例（Rust 进程级无头入口 + 临时目录）**
   - 在 `crates/tray` 暴露无头/测试环境变量注入点（临时面板端口、临时启动文件夹、stub `nexus-server`），用 `cargo test` 验证：
     - 命名 Mutex 单实例拦截；
     - `/api/status` 到三色状态灯与菜单状态的映射；
     - 退出时先走优雅关停、超时 3 秒则 Job Object **树杀**兜底且无孤儿进程；
     - 「开机自启」开关在临时目录正确创建与删除 `.lnk`。
3. **缝隙 3 — 热切换与防失联回滚（端到端临时运行目录切换）**
   - 在隔离临时运行目录（含独立 `config.json`、`oauth-store.json` 与可执行文件）直接执行部署/切换流程，验证：
     - 正常换核后 `/health` 200、`config.json` 与 `oauth-store.json` 零改动；
     - 投喂启动即崩溃的坏二进制后，10 秒内自动还原 `.prev` 恢复 `/health` 200 并产出可读失败日志；
     - 托盘自身哈希变化时走脱离进程树切换器完成替换与健康校验。

### 既有测试先例

- `tests/panel.test.ts`、`tests/tunnel.test.ts`（`startServer()` + `waitFor()` + `cloudflared` stub）
- `tests/packaging.test.ts`、`scripts/smoke-package.ts`（打包产物结构与配置优先级）
- `crates/executor/src/jobs_tests.rs`（`SPAWN_LOCK` 串行真实子进程测试与 Windows Job Object 树杀验证）

## Out of Scope

- 不引入 Electron、Tauri、WebView2 或任何桌面前端框架；所有配置表单与**服务日志**浏览留在浏览器**面板**。
- 不启用 GitHub Actions 或任何云端 CI workflow；全量验收继续走本地 `npm run check`。
- 不做代码签名与自动联网在线更新（只做本机开发仓到本机运行目录的**热切换**）。
- 不移除**执行层**默认的 `MSYS_NO_PATHCONV=1`。
- 不涉及 9 个 MCP 工具的契约变更，也不扩展多根目录或非 Windows 托盘实现。

## Further Notes

- **待实现期敲定的微细节（未在访谈中强约束）**：
  - 托盘三色图标的具体像素/ICO 绘制资源（可由代码内嵌轻量 ICO 或从现有 `icon.ts` SVG 派生）；
  - 托盘内部换核接口与优雅全停接口的本机鉴权细节（最低要求：仅绑定 `127.0.0.1`、拒绝非 loopback `Host` 头与跨站 `Origin`，与现有面板接口安全边界一致）；
  - 热切换前是否强制在脚本内串行跑完整 `npm run check` 还是提供 `--skip-tests` 供已跑完测试的 AI 跳过重复耗时（默认行为应确保测试已过、至少必跑新产物临时端口 smoke）。
