# 10: 隧道接入

**What to build:** 云端 AI 要一个 https 地址才能连进来，所以服务必须能拉起一条到本机的隧道，并且把地址显示在面板上、实时反映通断。这台机器上已有可用的 Cloudflare 命名隧道（固定域名），它指向的是旧服务；这张票把它接到新服务，并处理「进程挂了没人管」和「开机不自启」这两件事。

**Blocked by:** 01

**Status:** ready-for-agent

- [ ] 面板上一键启动与停止隧道进程，操作结果即时反映在状态灯
- [ ] 面板显示当前公网地址，并提供可达性检测（请求 health 端点）
- [ ] 隧道进程退出时状态灯变红，能看到退出码或最后几行错误
- [ ] 使用固定域名的命名隧道（本机已有 `config.yml` 与隧道凭据），不使用临时随机地址
- [ ] 新服务监听 8787，与现有隧道配置（`nexus.maliy.top` → `127.0.0.1:8787`）一致，`config.yml` 一行不改
- [ ] 不采用「改隧道配置指向其它端口」的做法，理由：那要动一个已经能工作的配置文件，且 Gemini 侧无需任何改动
- [ ] 明确记录端口占用代价：8787 同时只能有一个服务监听，接管前必须先停掉旧的 Bridge 进程
- [ ] 不尝试注册 Windows 服务或计划任务（本机实测两条路都不可用，原因见交接笔记）
- [ ] 提供开机自启方案：启动文件夹放置隐藏窗口启动器
- [ ] 处理「没有自愈」：给出守护方案（进程退出后重启），并说明代价是多一个常驻进程
- [ ] 交接笔记里的排障顺序原样保留在文档里，方便下次断线时照着查
- [ ] 记录沙箱限制：本机部分命令（注册计划任务、COM 实例化）需用户手动执行
