# 02: 本地控制面板

**What to build:** 服务同进程提供一个本地网页面板。打开浏览器就能看见服务是否正常、当前 MCP 地址、最近的日志，并且能不敲命令完成启停和改根目录。

**Blocked by:** 01

**Status:** done

- [x] 浏览器打开根路径能看到面板，一屏内包含：状态灯、MCP 地址、授权入口、根目录、日志、启停按钮
- [x] 三个状态灯分别反映执行器、MCP 服务、隧道的真实状态，不是写死的
- [x] MCP 地址可一键复制到剪贴板
- [x] 面板上修改根目录后立即生效，并持久化到配置文件
- [x] 日志区显示最近 100 行，可滚动，不泄露令牌
- [x] 停/启/重载配置三个操作可用，操作后状态灯随之变化
- [x] 不引入 Tauri、Electron 或任何桌面框架，面板由服务自身提供静态资源
- [x] 面板接口不接受跨站请求写操作（避免本地网页被别的页面驱动）

## Comments

实现拆成四个模块：`src/mcpService.ts`（原来 `http.ts` 的 MCP 端点，多了 `start/stop`）、`src/panel.ts`（页面与 `/api/*`）、`src/log.ts`（环形日志缓冲）、`src/status.ts`（执行器与隧道探测）。

两个决定值得记一下：

- 面板单独监听 `panelPort`（默认 `port + 1`）。这样「停止」能真的关掉 MCP 端点的 socket，面板自己不掉线；如果把两者塞一个 listener，「停」就只能做成暂停。
- 执行器灯如实显示「未接入」，等 03 票落地后改成真握手。没有做假绿灯。
- 隧道灯只有在 `config.json` 配了 `tunnelUrl` 时才探测，没配显示「未配置」。
- 写接口只接受 `application/json`，且 `Origin` 必须是本面板自己的；表单式跨站 POST 返回 415。

测试：`tests/panel.test.ts` 8 条，面板走 HTTP、MCP 侧走官方客户端。`npm run check` 通过（21 测试 + smoke）。

code-review（双轴）之后修掉的：

- MCP 状态灯的颜色映射缺了 `running`/`stopped` 两档，启停时灯一直灰着，已在 CSS 补上。
- 重载测试原来恒真（读磁盘和内存本来就是同一个值），改成先改磁盘上的 `root` 再重载，并断言旧会话在重启后失效。
- `/api/status` 里隧道探测改成 2 秒超时、页面轮询 5 秒一次，避免隧道黑洞时请求排队。
- 补了 Host 校验（挡 DNS rebinding）和相对路径 root 的 400。
- 测试启动逻辑抽到 `tests/support/server.ts`，两个测试文件不再各抄一份。

记录在案的取舍：spec 里「面板只读本地状态，不承载业务逻辑」与本票「面板能启停、改根目录」冲突，按后写的票执行——启停、改根目录、写配置都落在面板接口里；如果以后要回到「纯只读面板」，得先改这张票的验收。

未采纳的审查意见：「执行器灯是写死的」——执行器确实不存在，假绿灯比常量更糟，03 票落地后换真握手；「把内联 HTML 拆成独立资产」——单文件分发是这个项目的目标，拆了反而多一步打包。
