# 03: Rust 执行器骨架与 `bash`

**What to build:** 新增一个 Rust 可执行程序作为唯一的执行层，被协议层通过 stdio 调用。`bash` 工具第一次真正跑起命令：拿到合并后的输出和退出码，中文不乱码，跑太久会被杀掉，输出太长会截断并标注省略。

**Blocked by:** None（可以立即开始，与 01 并行）

**Status:** ready-for-agent

- [ ] 新增 Rust 可执行程序，通过单行 JSON 的 stdio 协议响应请求，请求带自增 id
- [ ] 协议层不再直接创建子进程，所有命令执行都经由执行层
- [ ] `bash` 在给定工作目录执行命令，返回合并的标准输出与错误输出，以及退出码
- [ ] 退出码非零时工具结果仍是正常返回（由模型判断），不标记为协议错误
- [ ] 默认使用 Git Bash，启动时设置 `LANG=zh_CN.UTF-8`、`LC_ALL=C.UTF-8`、`MSYS_NO_PATHCONV=1`
- [ ] 配置为 PowerShell 时只允许 PowerShell 7，显式指定 5.1 时启动即报错并说明原因
- [ ] 输出含中文时两端解码正确，不乱码
- [ ] 超过 `timeout_ms` 的子进程被终止，返回明确的超时信息而不是挂起
- [ ] 输出超过上限时保留头部与尾部，中间标注省略的字节数
- [ ] 执行器进程意外退出时，协议层返回可读错误而不是卡死等待
