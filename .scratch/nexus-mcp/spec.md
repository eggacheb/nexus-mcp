# nexus-mcp 规格

Status: ready-for-agent
Created: 2026-11-21

## Problem Statement

Gemini 网页版（`gemini.google.com` → 设置 → 关联应用 → 自定义 MCP 服务器）只接受 `https://` 地址加 OAuth 鉴权，没有填 Bearer 头的位置。现成的 Nexus 项目虽然补上了 OAuth 支持，但它的工具层对模型不友好：

- 332 个工具塞在一个近两万行的注册表里，每个工具带 `providerId`、`runnerAdapter`、`rpcMethod`、`safetyClassification` 等二十多个治理字段，模型读不懂也用不上；
- 读写一个文件要先调 `project_list` 拿 `projectId`，还挂着 `approvalId`、`sessionId` 这类模型无法判断该不该填的可选参数；
- 同名能力存在多份实现（`file_read` / `file_read_stream`、`file_delete` / `fs_delete`、`command_run` / `job_start` / `build_start` / `test_start`），命名互相打架。

结果是：连接能建立，但模型不知道该怎么用、该用哪个，实际干活效率很低。用户需要一套「工具少、语义清楚、不需要前置步骤」的本地能力接口，只覆盖真正高频的几件事：读文件、改文件、跑命令、找文件、搜内容、跑长任务。

## Solution

一个单目录沙箱的本地 MCP 服务，只暴露 8 个工具，由 TypeScript 协议层和 Rust 执行层组成：

- **协议层（TypeScript）**：MCP stdio 与 streamable HTTP 双传输、Bearer 校验、OAuth 2.1 授权、本地网页面板、配置加载、工具定义与参数校验。不含任何文件系统或进程操作权限。
- **执行层（Rust）**：命令执行、文件读写、补丁应用、路径沙箱校验、输出有界缓冲。通过 stdio JSON-RPC 被协议层调用，是唯一接触真实磁盘和进程的部分。
- **工具集**：`read`、`write`、`edit`、`bash`、`glob`、`grep`、`job_start`、`job_output`。一个工具一个动作，参数扁平，全部无状态，`path` 一律是相对沙箱根目录的路径或绝对路径，不需要先创建项目或会话。
- **默认 shell**：Git Bash（POSIX 语义，适配云端模型生成的命令），可配置切换到 PowerShell 7。所有子进程强制 UTF-8。
- **分发**：两个可执行文件（Rust 执行器 + TypeScript 协议层）加一个配置文件和一个启动脚本，用户机器不需要装 Rust 或 Node。

## User Stories

1. 作为使用者，我想让 Gemini 网页版读写我指定的一个项目目录，这样我在浏览器里就能改本地代码，不用来回切编辑器。
2. 作为使用者，我想让 AI 只能访问我指定的那个根目录，这样它不会误删系统文件。
3. 作为使用者，我想在 AI 访问根目录以外的路径时收到明确的拒绝信息，这样我能判断是工具用错了还是它在越权。
4. 作为使用者，我想读文件时拿到带行号的内容，这样我能直接引用行号跟 AI 讨论。
5. 作为使用者，我想按行号范围读大文件的一段，这样不会因为文件太长把上下文撑爆。
6. 作为使用者，我想让 AI 用「精确替换」而不是整文件覆盖来改代码，这样改动可控、diff 干净。
7. 作为使用者，我想在待替换的文本出现多次时让工具直接失败，这样 AI 不会改错地方。
8. 作为使用者，我想跑任意命令并拿到合并后的标准输出、错误输出和退出码，这样 AI 能自己判断命令是否成功。
9. 作为使用者，我想让超过两分钟的命令（构建、测试）转到后台执行并立刻拿到任务 id，这样工具调用不会超时中断。
10. 作为使用者，我想随时查后台任务的增量输出、退出状态和退出码，这样长任务不需要一直挂着等。
11. 作为使用者，我想按通配符查找文件，返回结果按最近修改排序，这样 AI 能先定位再读。
12. 作为使用者，我想在文件内容里按正则搜索并拿到文件名与行号，这样我不用把整棵树喂给模型。
13. 作为使用者，我想不管命令行输出中文还是英文都不乱码，这样读日志和测试结果不会被编码问题卡住。
14. 作为使用者，我想工具返回过长时自动截断并明确标注省略了多少字节，这样 AI 知道还有内容没看到。
15. 作为使用者，我想在浏览器里看到一个面板，显示执行器、MCP 服务、隧道三个状态，这样我不需要查日志判断是否正常。
16. 作为使用者，我想在面板上一键复制 MCP 地址，这样我直接粘到 Gemini 的自定义 MCP 配置里。
17. 作为使用者，我想在面板上改根目录并立即生效，这样换项目不用改配置文件再重启。
18. 作为使用者，我想通过 OAuth 完成授权，这样 Gemini 网页版能接受我的本地服务地址。
19. 作为使用者，我想通过隧道把本地服务暴露成 https，这样云端 AI 才能连进来。
20. 作为使用者，我想在面板上看到最近 100 行日志，这样出问题我能自己先看一眼。
21. 作为使用者，我想在面板上启停服务，这样不用开终端敲命令。
22. 作为使用者，我想让配置（根目录、端口、令牌、shell、超时）全部来自配置文件，这样我能改完就重启生效。
23. 作为使用者，我想把整个东西打包成两个 exe 加一个配置文件分发给别人，这样对方不需要装 Rust 或 Node。
24. 作为使用者，我想在提交前用一条本地命令跑完全部检查，这样我不依赖 GitHub Actions。
25. 作为使用者，我想控制命令白名单和危险命令拦截，这样 AI 跑 `rm -rf` 这类命令时至少有一层拦阻。
26. 作为使用者，我想关掉服务时后台任务一起结束，这样不会留下孤儿进程占端口。
27. 作为使用者，我想多个 AI 客户端同时连上来时互不串话，这样我可以边用 Gemini 边用本地测试客户端。
28. 作为使用者，我想工具的错误信息直接可读（说明哪个参数错了、为什么被拒），这样我能把原始错误贴给 AI 让它自己纠正。
29. 作为使用者，我想工具清单稳定不变（名字和参数定义不随意改），这样已经配好的客户端不会突然对不上。
30. 作为使用者，我想在 AI 连续改坏多个文件时能用 git 回滚，这样工具本身不需要内置撤销功能。

## Implementation Decisions

### 模块划分

- **协议层（TypeScript）**：只负责 MCP 协议、传输、鉴权、配置、面板。不直接调用 `fs`、`child_process` 做工具操作，避免权限分散。
- **执行层（Rust）**：单一进程，对协议层提供 stdio JSON-RPC。负责 `bash`、`job_start`、`job_output` 以及文件读写与补丁应用。
- **进程间契约**：请求与响应都是单行 JSON，请求带自增 id。协议层不感知 Rust 内部结构，只依赖方法名与返回字段。这个契约属于实现细节，不写测试断言报文格式。

### 传输与鉴权

- 同时支持 stdio（本机客户端、测试）与 streamable HTTP（云端 AI）。
- HTTP 模式默认监听 `8787`，与本机已有的 cloudflared 隧道配置（`nexus.maliy.top` → `127.0.0.1:8787`）一致，接管时隧道配置不需要改动。
- HTTP 模式用 Bearer 令牌校验，令牌为空时仅允许 loopback 访问。
- OAuth 2.1 授权服务复用 Nexus 桥接层已有的实现思路：RFC 9728/8414 元数据、动态客户端注册、PKCE S256、refresh token 轮换、令牌哈希后落盘。授权页要求输入本地令牌才能批准。
- 会话按 `Mcp-Session-Id` 隔离，一个会话对应一个独立的 server 实例，会话关闭时释放关联的后台任务引用。

### 工具语义

- 8 个工具，一个动作一个工具。禁止把多个动作塞进一个工具的 `action` 参数。
- 参数全部扁平，不引入 `projectId`、`sessionId`、`approvalId` 这类模型无法自主判断的间接层。
- `read` 返回带行号的内容；`offset`/`limit` 按行切分。
- `edit` 使用 `old_string`/`new_string` 精确替换，匹配不唯一时失败并提示「匹配到 N 处」。支持可选 `replace_all`。
- `bash` 返回合并输出与退出码，退出码非零不算协议错误，由模型自行判断。
- `job_start` 立刻返回 `job_id`，`job_output` 支持从指定字节偏移增量读取。
- 所有工具错误以「可直接展示给模型的一句话」返回，不使用堆栈。

### 沙箱与路径

- 单一根目录，由配置提供，绝对路径解析后必须落在根目录内，否则拒绝。
- 不做「尽力而为」的修补（不允许把 `..` 静默裁剪）。
- 符号链接按解析后的真实路径判断是否越界。

### 执行环境

- 默认 Git Bash：启动时设 `LANG=zh_CN.UTF-8`、`LC_ALL=C.UTF-8`、`MSYS_NO_PATHCONV=1`。
- 备选 PowerShell 7：启动时设 `[Console]::OutputEncoding` 为 UTF-8，使用 `-NoProfile -NonInteractive`。
- 显式拒绝 PowerShell 5.1。
- 子进程输出按 UTF-8 解码，解码失败时回退 GBK 再试一次。
- 输出缓冲采用有界环形结构：保留头部与尾部，中间以「省略 N 字节」标记。

### 复用决策

- 补丁的模糊上下文匹配算法从 codex 的 `apply-patch` 移植（`parser`、`seek_sequence`、`text_file` 三部分逻辑），文件系统后端换成自有 trait。
- 命令白名单与可执行名归一化从 codex 的 `execpolicy-rules` 移植。
- 输出有界缓冲从 codex 的 `head-tail-buffer` 移植。
- UTF-8 边界截断从 codex 的 `utils/string` 移植。
- 不引入 codex 的沙箱实现（`sandboxing`、`linux-sandbox`、`windows-sandbox-rs`）、`exec-server`、`network-proxy`，原因是依赖链会拖进 7 个 `rama` alpha 版本和整套云服务栈。

### 面板

- 本地网页，由协议层同进程提供，不引入 Tauri、Electron 或任何桌面框架。
- 一屏六块：状态灯、MCP 地址（可复制）、OAuth 入口、根目录选择、最近日志、启停与重载。
- 面板只读本地状态，不承载业务逻辑。

### 分发

- 产物为两个可执行文件 + `config.json` + 启动脚本，打成一个 zip。
- 协议层打包成单文件可执行程序，运行时不依赖已安装的 Node。
- 配置优先级：环境变量指定的路径 > 可执行文件同目录的 `config.json` > 内置默认值。
- 代码按跨平台写（路径、shell 探测都按平台分支），但只构建 Windows 产物。

### 本地 CI

- 一条命令跑完：类型检查、编译、测试、自检脚本。
- 不使用 GitHub Actions。推送 workflow 文件有账号风险，这条是硬约束。

## Testing Decisions

### 什么是好测试

只测外部可观察行为：从 MCP 客户端连上服务，调工具，断言返回的文本与 `isError`。不断言内部函数调用、不断言 Rust 与 TS 之间的报文结构、不断言日志格式。

判断标准：如果重构执行层（比如把 `bash` 从子进程改成伪终端），测试应该照旧通过。

### 缝隙

唯一跨组件缝隙：**MCP 客户端 ↔ 服务**。所有验收都从这里进。

- 启动服务（stdio 或 HTTP），用官方 MCP 客户端连接；
- 断言工具清单、参数校验错误、沙箱拒绝、真实执行结果、退出码、截断标记；
- 长任务用 `job_start` + 轮询 `job_output` 验证增量输出与结束状态。

Rust 执行层内部保留单元测试（补丁匹配、路径越界判定、UTF-8 截断），这些不跨进程，属于算法级验证。

### 既有先例

`tests/mcp.test.ts` 已经按这个形状写了四条用例：工具清单、描述非空、越界拒绝、根目录内路径放行。后续所有用例沿用同样的 `beforeAll` 连接、`afterAll` 关闭结构。

## Out of Scope

- 桌面原生应用（不引入 Tauri、Electron）。
- 多用户、多租户、权限分级。
- 332 工具那套治理元数据（`providerId`、`rpcMethod`、`safetyClassification`、`supports*`）。
- 项目授权、会话信任、审批中心等 Nexus 特有概念。
- 远程沙箱、容器化执行。
- GitHub Actions 与任何云端 CI。
- 本地模型的推理接入（本服务不含模型，模型始终在云端）。
- 自动更新机制。

## Further Notes

- codex 可复用组件的调研结论在 Nexus 仓库的 `docs/research/codex-reusable-parts.md`，移植前先读它，尤其是「哪些不能直接搬」那一节。
- Gemini 网页版必须走 https，本机调试时用 HTTP 直连测试客户端即可；真正接 Gemini 时需要隧道，隧道地址变化会影响已保存的配置，面板上要能重新生成。
- 工具清单一旦对外发布就当作稳定契约，改名或改参数视为破坏性变更。
