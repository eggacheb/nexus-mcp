# Domain Docs

工程技能在探索代码库前，应如何读取本项目的领域文档。

## 探索前先读这些

- 仓库根目录的 **`GLOSSARY.md`**；或
- 仓库根目录的 **`GLOSSARY-MAP.md`**（如果存在），它指向每个上下文的 `GLOSSARY.md`
- **`docs/adr/`**：读与本区域相关的 ADR

文件不存在就静默跳过，不要提示缺失，也不要在开工前主动要求创建。
`/domain-modeling` 会在术语或决策真正定下来时才创建它们。

## 文件结构

本项目是单上下文：

```
/
├── GLOSSARY.md
├── docs/adr/
│   ├── 0001-....md
│   └── 0002-....md
└── src/
```

## 用术语表里的词

输出中凡是涉及领域概念（票标题、重构建议、假设、测试名），一律使用 `GLOSSARY.md` 定义的词，不要改用术语表明确避免的同义词。

需要用的概念在术语表里没有，是个信号：要么是在发明项目不用的说法（重新考虑），要么是真有缺口（记下来交给 `/domain-modeling`）。

## 与 ADR 冲突时要显式说明

如果输出与现有 ADR 相矛盾，直接摆出来，不要悄悄覆盖：

> _这一条与 ADR-0007 冲突，但值得重开，因为……_
